# Deliverables: exec summary, proposal, paper, pitch deck

The guidebook's section order is mandatory. Use its exact headings. Inside that skeleton, apply the patterns below.

## 1. Universal writing rules
- **Answer first** (Pyramid): each section opens with its conclusion, then 2–4 supporting points, each with evidence.
- **Action titles**: section and slide titles are full-sentence insights. Write "Unplanned downtime cost $67M, 66% of it from 3 failure modes", not "Downtime Analysis".
- **So what** at the end of each analytic block.
- **Numbers carry units, a period and a source.** Write "Rp80 miliar capex (2027–2029)", not "big investment".
- Short sentences. One idea per paragraph. Prefer tables and diagrams over prose for comparisons, processes and roadmaps.
- Use the client's vocabulary. Name their plants, systems, roles and philosophy.
- Cite sources in the required style (APA by default). Put every external benchmark in the references.

## 2. Executive summary (preliminary, ~5–7 pages)
Allocate pages by rubric weight. A typical flow:
1. **Problem identification & analysis** (largest share): an SCQ opening in 3 lines → the hook number → the root-cause framework visual (fishbone, causal loop, issue tree) → 2–3 quantified root causes.
2. **Strategic recommendation**: the big idea in one sentence + 3–4 pillars, each tagged with the root cause it solves, and why this approach beats the obvious alternative.
3. **Implementation direction**: a phase table (phase, focus, key activities, owner, timeline).
4. **Expected impact**: a KPI table (baseline → target) + headline financials (illustrative NPV/payback, with assumptions in the appendix).
5. References · Appendices (data analysis, assumption table, framework details).

## 3. Proposal (semifinal, ~12–15 pages)
It deepens the exec summary and doesn't replace it. Add:
- **Business & problem analysis**: fuller data analysis, validated assumptions, and alternative hypotheses that were ruled out.
- **Proposed solution**: initiative cards, architecture/process diagrams, and the human role in each step.
- **Value proposition** per stakeholder.
- **Implementation roadmap**: a Gantt-style chart with phases, milestones, gates, resources (FTE, budget) and governance.
- **Feasibility**: technical, organisational, financial and regulatory, with evidence (benchmarks, pilots, prototype).
- **Impact & measurement**: a value driver tree, a financial model summary, sensitivity, a KPI dashboard and the measurement cadence.
- **Risks & mitigation** (if not a separate section, put it under Feasibility).
- **Conclusion**: restate the answer and the ask.
State visibly what changed since round 1, and how it addresses the feedback.

## 4. Technical paper (e.g. actuarial)
Abstract/executive summary → introduction (the management question) → data & methodology → results by workstream → diagnosis → recommendations → sensitivity → conclusion → references → appendices (formulas, full tables, model description). Mirror the case workstreams. Number tables and figures consistently and refer to every one of them in the text.

## 5. Pitch deck
- Respect the slide cap and what counts toward it. CALIBER's 7 slides **including** the cover is very tight, so plan one message per slide.
- Ghost deck first: write all the action titles in order and read them alone. They should tell the full story (the "red thread" test).
- Typical arc: Context & key problem (with the hook) → root cause → solution (big idea + pillars) → how it works (a demo or flow visual) → value proposition → roadmap → feasibility → impact (big numbers) → risks → conclusion and ask.
- One visual per slide. Big numbers. Keep text to what the speaker needs as an anchor.
- An appendix with backup slides for the expected Q&A (assumptions, sensitivity, architecture detail, cost breakdown).
- Use the `pptx` skill to build it (or `academic-pptx` for technical defences), and `dataviz` for charts.

## 6. Prototype & video (when required)
A link to the hosted prototype plus a 2–3 minute video. Video arc: the problem in 20 seconds → one user story end to end on real case data → the impact number → close. Put the links on the deck and test them in a private window.

## 7. Format pass
Apply the guidebook format exactly (font, size, spacing, margins, paper, page limits and what is excluded, cover elements and logos, file name, file size). For anonymity rules, clean the PDF metadata (Author, Creator), headers and footers, the file name and any links that reveal identity. Embed fonts in the PDF. Export, then reopen and check every page.
